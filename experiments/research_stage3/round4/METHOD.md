# Stage3 round4: repair the observation API contract

Round3 identified an incorrect transfer from holder-world-X displacement to socket-X error. The native task reads the current plug pose and recomputes gripper-to-plug and socket transforms before transport. The added contract computes the world-to-socket vector using NumPy and labels units, frame, source and uncertainty. It does not supply a successful action or assert a displacement-to-error response model.

[Code as Policies, §III](https://arxiv.org/html/2209.07753v4#S3) studies perception-grounded robot programs calling control APIs and using numerical libraries for geometry. Its [Interactive_Demo source](https://github.com/google-research/google-research/blob/master/code_as_policies/Interactive_Demo.ipynb), LMP_wrapper.get_obj_pos/get_bbox/put_first_on_second, explicitly uses robot-base coordinates; denormalize_xy maps coordinate conventions in code. We read these functions and the paper method. We reuse this API-grounding principle, not its PyBullet/UR5 runtime or arbitrary-code executor. The local original task already implements the required transforms; only a small observational description is added. No dependencies or simulator changes.

Code as Policies is not evidence that this fix works. Four frozen, actual model/physics trials test it. Extra geometry/primitive semantics are explicitly part of the candidate treatment; success cannot be attributed solely to improved reasoning with identical information. Held-out means a new initial condition, not a new task. All conclusions use privileged simulator information and remain Simulation-only.
