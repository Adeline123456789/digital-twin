# Stage4 round1: improve experiment selection at the first failed primitive

Historical outlet1 runs fail during transport IK, before insertion. Changing insertion offsets did not fix that phase. Current native task source exposes preinsert-gap and states the carry tilt is intended to keep the raised approach within joint limits. Probe that existing parameter, retaining the5-degree branch at every candidate. Each saved goal must first be reconstructed to1e-8m. Native PoseIK performs its existing bounded SciPy least-squares solve; no solver, bounds or acceptance thresholds are changed.

[ASPIRE §2.1–2.2](https://arxiv.org/html/2607.00272v1#S2) localizes failures from primitive traces, tests a targeted repair and retains verified conditional knowledge. Its multi-angle-approach example changes an infeasible navigation goal instead of repeatedly changing perception or grasping. We read this method and [OmniGibsonCuroboPlanner.solve_ik / _full_result_outcome](https://github.com/NVlabs/ASPIRE/blob/main/src/cap_harness/behavior/planning.py), which preserve the measured/selected seed, distinguish IK failure and expose planning diagnostics. Their cuRobo/OmniGibson/R1 implementation is incompatible with this Piper scene and would add a large dependency; only the diagnostic mechanism is adapted, using existing PoseIK and saved simulator state.

This is a numerical diagnosis/experiment-selection test with zero model calls and zero physics steps. It cannot establish path collision safety, stability, task success, or reduced cost per valid Episode. Candidate gap changes need later native full-task execution and holdout validation before skill admission. Privileged state, object transforms and IK results are disclosed; no measured force, RGB-D or real calibration is claimed.
