# Historical experience must reach the execution entry

The latest paired real failures existed as `NE020`, but the default right-arm feedback branch supplied an empty memory list. The old signature lookup also missed NE020 and selected the first five matching filenames. A stored report was therefore not evidence that the planner could use the experience.

The shared lookup now ranks source-Episode matches first, then matching phase, and checks explicit applicability. Right-arm use excludes legacy entries with only prose applicability unless they reference that exact source Episode. NE020 v2 adds right-arm/original-profile/socket-3 scope and the generic insertion-failure signature. Its two real failures, unverified first recording export, UNKNOWN root cause, evidence references and proposed next checks remain together. It is a historical warning, never a measurement of the present fixture, a verified repair or permission to replay.

`agent_loop.run` now supplies the cards at the default `llm` planning boundary and after execution feedback. `bounded_tools.plan` and `diagnose_repair` use the same cards. Retrieval IDs/content are recorded. No motion, success detector, speed, force setting, XML or raw Episode changed. The recipient benchmark explicitly supplies an empty live-memory snapshot at both planning and diagnosis boundaries; only its frozen guidance and design evidence remain available. Its previous scores are not rerun or reinterpreted.

## Primary sources checked and limited reuse

- **Agent Workflow Memory:** [paper §2.2–2.3](https://proceedings.mlr.press/v267/wang25bx.html), official [memory.py](https://github.com/zorazrw/agent-workflow-memory/blob/8c0ff8cd11d648c8fceb99e4e42f37e3b75381b1/mind2web/memory.py) and [workflow/retrieve.py](https://github.com/zorazrw/agent-workflow-memory/blob/8c0ff8cd11d648c8fceb99e4e42f37e3b75381b1/mind2web/workflow/retrieve.py), Apache-2.0. The source filters exemplars by website/domain and also offers embedding-based workflow selection. We adapt selective, scoped experience delivery to the existing small JSON corpus; no source copied, embedding service or web-agent framework installed. AWM induces workflows from successful web experiences; our negative-evidence cards are an application-specific adaptation, not an AWM reproduction or a newly verified successful Skill.
- **SKILL.state:** [full paper §3.1–3.2 and Algorithm 1](https://aclanthology.org/2026.emnlp-industry.264.pdf) uses an explicit execution state and current observation instead of reconstructing state from appended dialogue. No official full implementation was verified here. Our bounded planner already supplies structured state and limited tool evidence, but retains prior tool events. This patch does **not** implement the complete SKILL.state transition runtime and cannot disable Codex desktop's context compaction. Full durable state transitions remain a separate unverified gap.
