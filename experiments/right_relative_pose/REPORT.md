## 实际入口

`scripts/agent_loop.py --fastslow --relative-precontact` 进入 `collect_current_scene.main → benchmark_collection.run_case → learn.simulate → collect_inline.collect`。可选路径在本地载入按哈希绑定的第 3 轮求解器版本，加入测量与阶段回调，继续使用原 `place_over_socket → PoseIK.solve → move → checked_physics_step` 和记录器。它用 `T_WS @ T_SP_desired @ inv(T_GP)` 求工具目标。该变换原来就在原生仿真内，本轮新增的是测量输入、分段拒绝、结果消费和有边界的诊断。保留的旧入口与旧求解器字节可直接回滚，V2.1 仍为 NO-GO。[原架构决定](../../V21_REINTEGRATION_REPORT.md)

同一任务 ID 的 `relative_result.json` 保存来源、时间、坐标、目标和前后残差。收集返回时，`consume_trial` 核查单臂视频、HDF5、物体轨迹与相位。合格片段用既有 `resample` 冻结到 100 Hz，再走 `validate_shared_reference.validate`。回放逐积分步检查穿透与禁碰，按观测帧检查手内插脚位移，末端检查所有插脚顶点的横向和轴向误差。模型间隙为 0.8 mm，本次将它也用作仿真预插入高度的保守误差限。通过后返回 `PRECONTACT_VALIDATED / STOP_AT_PRECONTACT`。诊断参考保留 `task_success=false`，原全任务加载器拒绝执行。每个消费结果写回当前检查点。

出现未知失败时，现有 `Supervisor` 处理 Failure Capsule 和按右臂、第 3 孔限定的历史经验。可用的运行时接口为已安装的 `deepseek-review`，一次最多请求一个离线检查，超时 45 s，回包验收上限 16,000 tokens。参数、控制代码、现场执行均不交给模型。开发期 +X 拒绝在恢复同一已停止仿真结果时成功调用 DeepSeek，模型选择几何检查，工具加载本地末状态，返回 6 个手指与黄色插头接触点，根因仍是 UNKNOWN。正式 +X 条件中模型超时，本地核对原 IK 错误和 0 帧命令后返回 STOP。两者均无动作重试。没有验证模型提出修复后自动恢复插入的能力。
