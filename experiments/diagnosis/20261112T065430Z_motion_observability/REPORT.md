# 机器人运动输入审计

现有多轴素材具备非退化的机器人侧旋转激励；视觉尺度和相机位姿仍未验证。没有新物理参数拟合或真机运动。

依据已阅读的 [Bi-JCR §III-C 式 12–14](https://arxiv.org/html/2505.24819v1) 及实际 [OpenCV Park 源码](https://github.com/opencv/opencv/blob/4.5.4/modules/calib3d/src/calibration_handeye.cpp)，分析相对旋转构成的 R-I 堆叠矩阵；与源码 I-R 符号相反，奇异值相同。未复制框架。

| 指标 | 全五帧 | 前四帧 |
|---|---:|---:|
| 秩 | 3 | 3 |
| 条件数 | 1.929 | 2.046 |
| 最小奇异值 | 0.17268 | 0.13676 |
| 线性右侧残差范数放大上界 | 5.791 | 7.312 |

最大相对旋转 9.399°，末端原点最大间距 8.554 mm。1/sigma_min 是固定旋转线性系统的算子范数，不能解释成像素转毫米系数或实际测量置信区间。成对方程共享姿态，不能按独立样本推断统计精度。满秩只排除了这一机器人侧退化，不验证单目尺度、内参或视觉对应。

759 帧相对 27 帧仅移动 0.226 mm、旋转 0.166°，且属于同一录制。它可以检查返回一致性，不能替代独立录制和充分姿态覆盖的验证。前四/第五帧划分仅作覆盖审计，未据此拟合。

现有 prepare_rgb_handeye.py 和 solve_rgb_handeye.py 已输出这些诊断；没有修改求解方法、候选接受边界、部署或安全控制。重新准备后机器人位姿逐项保持不变。新增测试说明两组同为满秩的运动可有约百倍绝对敏感度差异，同时验证单轴秩亏。全套 39 项测试通过。

camera.json 含 K/畸变元数据，本审计没有认定其为已验证的 RGB 内参，也没有使用其中深度字段。当前适配器要求米制目标位姿；Bi-JCR 的尺度联合求解说明这不是所有 RGB 方法的普遍前提。下一步应检查实际视觉约束，不应因为机器人侧满秩就声称已标定。

一次报告生成误用了不含 cv2 的默认 Python，记录为基础设施错误；改用已有系统 Python 后成功，没有安装依赖。源数据、位姿和相机配置留在本地，公开仅摘要及哈希。Stage 2 仍为六轮，无校准晋升或采集效率结论。
