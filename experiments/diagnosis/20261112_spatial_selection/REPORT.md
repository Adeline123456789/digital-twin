# 同点数预算的空间采样候选：不晋升

直接针对左侧聚集问题，读取 [ORB-SLAM §V-A](https://arxiv.org/pdf/1502.00956) 与 [ORBextractor 源码](https://github.com/raulmur/ORB_SLAM2/blob/master/src/ORBextractor.cc) 的空间分配机制。没有引入 SLAM 框架，也没有声称实现完整 ORB：仅用原 OpenCV GFTT 候选，在 3×2 区域轮流选点。阈值 .01、点间距 4、上限 30、原遮罩、LK 与 RANSAC 全部保持不变。没有按区域降低检测阈值。

旧四个开发变换由 3/4 变为 4/4。随后冻结 seed=507 的八个新变换（见 design.json），在同一运行环境比较，未根据其结果调参：基线 4/8，候选 6/8。它们仍来自同一张真实 RGB 的合成图像变换，不是独立物理数据或机器人成功率。

平均改善没有消除退化。heldout_2 的候选仅存活四点，P90 从基线 170.533 px 恶化到 1008.294 px；两个算法均严重失败。四点拟合成功不能证明区域外推有效。全部失败保留，没有修改原判定阈值。

历史 RGB 配对中，候选存活 26/29/28/29 点。前三组最接近的可见旋转与机器人角度差为 1.894/1.707/0.221°，对照此前约 0.150/0.094/0.183°；返回组虽从 1.277° 降至 0.892°，仍不能确定真实精度。详见相邻 20261112T070219Z_544d90a8 结果。没有按最小角度差硬选位姿，也没有做新物理标定。

因此默认仍为 global；distributed 仅保留为可复现的显式实验选项。41 项软件测试通过，只证明软件行为，不推翻候选实验失败。原始数组本地保存；没有改变机械臂速度、安全规则、MuJoCo 参数或 Episode 格式。单次运行时间保留于 JSON，不声称采集总成本下降。
