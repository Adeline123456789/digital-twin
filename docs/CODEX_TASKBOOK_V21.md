## 验收关口 A：先证明快慢诊断是否有用，纯离线，不开启真机

用 **同一批** 右臂真机历史成功和失败 Episode、当前配置对应的右臂仿真成功和失败 Episode，冻结数据版本、场景/模型版本及诊断器版本。不能拿旧双臂示例直接代替右臂；旧双臂只作额外兼容性回归。对 Legacy 和 V2 分别处理每条相同证据，不得人为冻结 Legacy 的正常反馈权限，也不得允许 V2 使用额外的真实真值冒充公平对照。

比较：能否找到第一个可观察异常、是否把后来的 IK 报错当根因、误报警/漏检/UNKNOWN、结论是否有证据、下一项检查是否可执行且有区别力、是否阻止已知无效修复。独立真因未知时，不能声称根因诊断准确率；只报告有审查证据的事件定位及原生物理结果。必须同时报告完整冷启动、已有缓存热启动、读盘/解码、模型调用、仿真检查、端到端墙钟、Token 与调用次数；运行时、开发主 Agent 与子 Agent 成本分开，不计量处写 UNKNOWN，不能写 0。将可复用诊断与成本进行同源对照，报告独立 Episode/唯一轨迹数量，重复相同哈希不能当独立样本。

**决策 A**：V2 只有在提供更有用或不劣的诊断/实验选择，并且成本有可信解释时，才进入接线关口 B。若仅在单帧微基准好看、完整过程更慢且没有可行动增益，保留离线工具、拒绝当前 V2 升级，出具 NO-GO；不要追加 14 轮或用更多模型调用堆证据。关口 A 可以使用现有离线数据完成，不需要新的完整仿真和真机动作。

## 验收关口 B：接回原有右臂仿真任务，先 opt-in，再做 A/B

若 A 值得继续，将 V2 **增量接入**现有右臂任务流程，而非建立平行仿真器：

`当前右臂任务 → Supervisor → 原执行/规划器 → 原 MuJoCo 与记录器 → 结构化事件/原生结果 → FastLoop → 已验证 Skill/历史否决；必要时 Slow 选择已有诊断工具 → 生成受约束候选 → 原仿真执行并录制新 Episode → 原 validator 与成功判定 → 结果回 Supervisor → 保留、拒绝或 UNKNOWN → 更新适用记忆与检查点`。

重要：V2 不能再“生成 request 就返回”。必须在隔离、非真机的模式下，通过现有仿真采集器处理请求、收到真实新 Episode 结果并检查后置条件。保留 `--offline --fastslow` 的诊断用途，新增的右臂 `--fastslow` 或等价 opt-in 参数不得与离线模式混淆；默认仍 Legacy 直到验证收益。不能换新的训练 Episode 格式、替换原安全判定或从零写运动控制。旧双臂 VS002 不得自动晋升右臂技能；适用条件错误应返回 UNKNOWN。

真实 RGB/编码器事件和仿真特权事件属于不同观察源，V2 不得因为真实记录没有 `sim.privileged_contact` 就假装没有问题，也不得凭颜色或电机指令虚构精确接触力与 6D 持物姿态。对当前插接失败，优先复用真实历史缓存和可疑接触窗口；先查指尖几何、真实开度映射和夹爪内相对位姿的证据，不把摩擦设成默认根因。不在当前任务中重新搭建房间或修改无关物理参数。

用当前右臂同场景、同初始化定义、相同任务成功判定、相同安全约束和匹配的模型/仿真预算，对 Legacy 和 V2 分别做小规模、**真正不同且有信息量**的仿真任务／诊断比较。至少包含既有可成功条件、实际失败条件、一个有证据支持的场景状态变化或修复候选；若条件无法安全复现，明确阻塞而非造样本。冻结开发和最终验证案例。原双臂场景继续跑最低限度回归，不混合成功率。

**决策 B**：V2 必须被实际右臂任务入口调用，并能产生新执行与验证结果、记录候选是否改善、保持旧功能。若只生成文档、检查报告或停在 pending postcondition，不算通过。未证明优于 Legacy 时继续保持 Legacy 默认，V2 作为离线诊断侧车。不要为了“看起来有新系统”强制替换旧入口。

## 真机前的执行边界：先完成纯模拟硬件拒绝测试

此前的离线检查已发现：更换采集目录可能重复发送同一请求；旧场景 YAML 可能搭配旧冻结轨迹；缺冻结参考可能走 legacy 后门。必须在 **现有真实执行入口** （而不是只在新 Supervisor 里写提示词）增加或复用：唯一执行请求 ID 与幂等状态、场景/机器人配置/相机与控制器版本、完整轨迹哈希、验证结果、过期和拒绝原因。正在运行、结果未知、失败或未授权的旧请求不得因恢复聊天、重启进程、换目录而自动再执行；经新的审批明确标注重复性验证，才可将同一参考用于不同新试次。

用 mock CAN/硬件阻断完成测试：旧请求、场景变更、参考不匹配、缺冻结验证、重复请求、进程中断、结果未知都必须在真正发运动命令前拒绝。保持现有速度、限位、急停、滑移保护与停止流程，不把“提高成功率”理解成降速、增加不必要平滑或取消保护。若任一拒绝测试失败，直接停在 B，不进入真机。

## 验收关口 C：将来的真机对照（**不是本指令自动授权动作**）

目前检查点记载 `hardware.execution_allowed=false`。本指令只负责准备验证方案，不清零旧停止状态；任何真实动作需要**新的用户明确授权、现场就绪确认、现有安全检查**，且先通过 A、B 和执行边界。不能利用用户问“之后如何实验”作为恢复硬件的许可。

获得许可后，先做低风险的静态/观测及冻结参考检查，确认环境当前状态与任务前提；只有存在真实观测支持、预测变化明确且原仿真/安全检查通过的候选，才安排**一次**有目的的真实试次。先固定模型、轨迹和初态；真实机械臂由原 Piper 控制代码执行同一冻结仿真参考，V2 可以作为影子诊断与阶段性只读观察，但不能让慢 LLM 在运行中任意修改电机指令。真机结果、RGB、状态、命令、摄像头时序、人工复位和失败保护全部照原 schema 归档到各自目录。

第一次真实执行若失败：停止相同候选的盲目完整重试，把证据交给已有诊断路径，先回答哪个新观测能区别主要假设；没有充分新证据则标 DEFER_UNKNOWN。若成功：仍只代表单次成功；候选版本冻结后，按用户此前提出的 5 次独立复位小批量、5/5 物理成功及数据有效作为**阶段性验收门槛**，不得把 5/5 说成统计学证明 100% 成功率。任何测试中不能边试边修改高度、力矩、摆正间距，又将结果当同一冻结策略的成功率。

C 必须回答：相比 Legacy 或历史同条件参考，V2 是否实际减少重复诊断、无效尝试、人工干预、模型耗费，是否改善有效真实成功数据的采集效率；若证据不足，承认没有证明。任何真实成功均需独立物理成功检查，仿真成功、流程执行结束和 100 Hz 轨迹回放不能代替。用户尚未授权前不得自动运行 C。

## 预算、历史与自进化

不再按固定 P0–P4 轮次完成任务，也不重新用完“剩余 22 次仿真额度”。每个验收关口预先写明实际成本边界、可用工具、最小有区分力的对照和停止条件：先无模型的缓存/历史回放，再必要的模型诊断，再必要的新完整仿真。单个未解异常若没有新观测或有区别力的决策，不反复调用大模型；阶段数和研究周期由证据决定。将 Codex 外层 token、子 Agent token、正常执行 token、运行时间和人工成本分开记录，不以“运行时0 Token”宣称项目研发成本免费。

使用已有 `evolution/current_state.json` 作单一续作状态，不把全部历史对话喂给运行时。每个可复核的新证据/改动节点记录版本、问题、被排除的解释、候选、预测、实际结果、回滚位置、下次是否可以直接复用。只有在后续独立数据上真正有效的诊断/修复，才可升级为默认技能；如果改动仅提升了特定报告处理速度，标为工程优化，不宣传成真机成功或通用自进化。

本批暂停教师—学生、任务泛化、叠毛巾和新场景大规模构建；这些仍是长期目标，不可自动挤占当前修复预算。保持原双臂资产和右臂配置，未来切换属于后续阶段。
